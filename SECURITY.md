# Security

## Supported versions

Security fixes are applied to the **currently deployed** production site. Older builds are not maintained separately.

## Reporting a vulnerability

**Do not** open a public issue with step-by-step exploit instructions or sensitive proof-of-concept code.

Instead:

1. Open a **[new issue](https://github.com/andyofengland/GridGame-Web-issues/issues/new)** with the title prefixed `[Security]` and describe:
   - The type of issue (e.g. authentication bypass, data exposure)
   - Affected area (sign-in, game play, API, etc.)
   - Impact in plain language
2. Ask for a private way to share technical details if needed.

If GitHub **Private vulnerability reporting** is enabled for this repository, you may use that flow instead.

We will acknowledge reports as soon as we can and work on a fix in the private codebase before disclosing details publicly where appropriate.

## Out of scope

- Social engineering
- Denial-of-service against production without prior agreement
- Issues in third-party services outside our control

Thank you for helping keep Gridlocked safe for players.
