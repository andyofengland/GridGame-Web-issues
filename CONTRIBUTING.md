# Contributing — reporting issues

Thank you for helping improve Gridlocked. This repo is the right place for **bugs**, **defects**, and **product feedback**. You do not need access to the private code repositories to participate.

## Before you open an issue

1. **Search [existing issues](https://github.com/andyofengland/GridGame-Web-issues/issues)** — someone may have already reported the same problem.
2. **Use the templates** when possible — they prompt for information we need to reproduce bugs.
3. **One problem per issue** — easier to track and close when fixed.

## Bug reports

Help us reproduce the problem:

| Field | Why it matters |
|-------|----------------|
| Steps to reproduce | Lets us follow the same path |
| Expected vs actual | Clarifies whether it is a bug or misunderstanding |
| Browser / OS | Many issues are browser-specific |
| Game mode | Local, vs computer, or remote multiplayer |
| Signed in? | Passkey vs email-only flows behave differently |
| Build / version | Shown in the site footer when playing (e.g. `build 42`) |

Attach screenshots or short videos when they show the problem clearly.

## Feature requests

Use the **Feature request** template. Describe the problem you are trying to solve and your idea — not only the solution. We may implement something different that meets the same need.

## What happens after you file an issue

1. A maintainer reviews and may ask follow-up questions.
2. Valid bugs are linked to tasks in the **private** development repositories.
3. When a fix is deployed, the issue is closed with a short note where possible.

We cannot guarantee timelines. Critical bugs (data loss, security, unable to sign in) are prioritised.

## What not to post here

- Source code patches for the private repos (we cannot merge PRs against code that is not in this repository)
- Spam, abuse, or issues unrelated to Gridlocked
- Credentials, session tokens, or personal data beyond what is needed to describe the bug

## Code contributions

Application source code is not hosted in this repository. If you are interested in contributing code, mention that in an issue and maintainers can discuss options. Day-to-day development happens in private repos.
